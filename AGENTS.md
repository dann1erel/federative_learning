# Работа с репозиторием

Проект сравнивает стратегии федеративного обучения свёрточной сети для классификации изображений. Flower моделирует сервер и клиентов на одной машине, PyTorch обучает модель на размеченных клиентских выборках. Исследовательский вопрос — как неоднородность распределения классов между клиентами влияет на качество общей модели при разных стратегиях.

## Точки входа

Рабочий каталог приложения — `quickstart-pytorch/`. Пути ниже указаны относительно него. Корневой `main.py` только печатает приветствие. В `README.md` приложения описаны команды и форматы артефактов. Корневой `updates.md` описывает более раннюю стадию проекта. Актуальные значения параметров и доступные стратегии см. в `pyproject.toml` и `pytorchexample/strategies.py`.

В Linux или WSL перейдите из корня репозитория в рабочий каталог и активируйте его окружение. Для новой копии создайте его командой `python3 -m venv venv` внутри `quickstart-pytorch/` и установите зависимости через `python -m pip install -e .` после активации.

```bash
cd quickstart-pytorch
source venv/bin/activate
python -m unittest discover -s tests -q
```

Посмотреть план пилота и статус повторного использования каждого запуска можно без обучения.

```bash
python scripts/run_benchmark.py --config configs/aggregation_pilot.toml --dry-run
```

Для отдельного эксперимента с подготовленными данными HAM10000:

```bash
python scripts/run_experiment.py --config configs/ham10000_dirichlet.toml --num-clients 10 --rounds 3 --strategy fedavg
```

## Как проходит эксперимент

1. `scripts/run_experiment.py` читает значения из `[tool.flwr.app.config]` в `pyproject.toml`, применяет переопределения из TOML и затем из командной строки. Обёртка создаёт каталог запуска, передаёт Flower абсолютные пути к данным и результатам и вызывает `flwr run`. Число виртуальных клиентов передаётся через `--federation-config`.
2. `pytorchexample/task.py` задаёт CNN, преобразования изображений, разбиения и метрики. Поддерживаются CIFAR-10, HAM10000, FER2013 и Cassava. Скрипты `scripts/prepare_*.py` готовят данные. CIFAR-10 загружается из локального DatasetDict при его наличии или через Hugging Face. Для остальных наборов стандартный путь загрузки использует CSV-манифесты со ссылками на изображения.
3. `pytorchexample/server_app.py` инициализирует модель с заданным seed и запускает стратегию. В каждом раунде `client_app.py` получает глобальные веса, выбирает свою часть данных по `partition-id`, обучает модель и отправляет обновлённые веса и метрики. Соответствие между серверной стратегией и клиентским алгоритмом задаёт `strategies.py`. Локальные алгоритмы реализованы в `local_training.py`, серверная логика для FedNova и SCAFFOLD — в `custom_strategies.py`.
4. Сервер агрегирует обновления и оценивает общую модель. В `round_metrics.csv` источник `centralized_test` означает оценку на общей тестовой выборке, а `federated_validation` — оценку на локальных валидационных выборках клиентов. Для второй сервер суммирует матрицы ошибок и по общей матрице вычисляет accuracy, precision, recall и F1. Loss взвешивается по числу примеров.
5. `pytorchexample/experiment.py` отвечает за запись артефактов, `experiment_plots.py` — за графики. В каталоге запуска ищите статус и конфигурацию в `experiment.json`, вывод Flower в `console.log`, историю раундов в `round_metrics.csv`. Флаг `--save-model` включает сохранение итоговых весов.

## Разбиения и серии запусков

- IID служит базой для сравнения. Разбиение Дирихле по меткам моделирует разные доли классов у клиентов. Значения приложения по умолчанию — CIFAR-10, FedAvg и `dirichlet-alpha = 0.5`.
- В стандартных манифестах HAM10000 несколько фотографий могут относиться к одному поражению кожи. При распределении между клиентами и локальном делении train/validation код сохраняет группы `lesion_id` целиком. В режиме `natural` клиенты соответствуют значениям `source`, и их число должно совпадать с числом источников.
- `configs/aggregation_pilot.toml` задаёт два сценария (CIFAR-10 и HAM10000), девять стратегий, десять клиентов, три раунда и seed 42. Для измерения неоднородности самого разбиения есть `scripts/analyze_heterogeneity.py`.
- `scripts/run_benchmark.py` разворачивает план в отдельные эксперименты и ведёт `benchmark_state.json`. Завершённый запуск используется повторно после сверки его манифеста. `scripts/collect_benchmark.py --state results/aggregation-pilot/benchmark_state.json` собирает результаты этой серии в `results/aggregation_benchmark.csv`.
- Текущее состояние экспериментов, расхождения с планом и решения перед следующими запусками собраны в `исследование/Состояние_экспериментов.md`.
- `data/` и `results/` — локальные каталоги, исключённые из Git. В `dataset_examples/` хранятся примеры изображений и распределений классов. Проектные планы находятся в обеих папках `docs/`, а литература — в корневой папке `источники/`.
